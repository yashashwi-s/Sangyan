## Concrete corrections

1. **Private family handoff is deliberate.** Family/nominee notes and record locations start unchecked, including after restoring a different workspace. The sheet preview updates before export. Existing plain-language disclosure says the downloaded family copy is not password protected. Institution/type/status remain in the sheet, along with optional nickname/last-four references: this is a family record, not an anonymous export. Private record notes remain excluded.
2. **A delayed export cannot outlive its session.** Font preparation for Meitei/Santali can be asynchronous. Previously, clearing/navigating during that wait could still download the captured private sheet. Export now checks its session generation, current view/language and sharing choices before download. A cancelled failure cannot write a stale status into the replacement view. Changing sharing choices invalidates an in-flight export.
3. **Clear removes decrypted state and private dialog content.** It resets the account list, selected identifiers, unfinished drafts/editors, pending links, live status, sharing choices and dialog DOM. If a browser copy exists, the confirmation offers its removal through an unchecked, explicitly chosen option. Storage refusal is reported rather than claiming removal. Downloaded files remain separate and are not deleted by browser code.
4. **Saved departure and unsaved recovery are distinct.** Departing a clean/saved session clears decrypted state before a potential back/forward-cache return; encrypted files/device copies can be reopened with the password. Unsaved work is retained rather than silently destroyed. The existing leave warning now also covers retained editors. An unsaved tab/back-forward-cache remains a shared-device exposure until the user saves/clears or closes it; browser leave prompts are not guaranteed on every mobile lifecycle. This is not a universal automatic lock or memory-zeroisation claim.
5. **Save/import work is bounded and failure-safe.** A busy vault submit cannot start a duplicate cryptographic operation. Stale errors are ignored after a new session generation. Regression coverage executes the actual vault handler with real encryption: corrupt input leaves the existing record/editor intact; a 50-account saved workspace restores its unfinished draft and partial editor even when the saved language cannot be fetched, using the available current language.

## Privacy boundary and shared-device behavior

Account fields, notes, passwords and decrypted files stay within page memory; the only optional persisted private object is the authenticated encrypted browser envelope. Reading preferences are nonfinancial settings. Public dictionary/audio/font requests do not contain account inputs. The service worker caches public assets and rejects private/query/POST interception. There is no account database, user login, speech/translation inference API, user-data logging or analytics integration in this app. A host still handles normal public asset request metadata; absence of app telemetry is not a claim that a hosting provider has no access logs.

A deliberate family sheet and calendar file are local downloads. Family sheets are readable and may contain the selected personal notes/references; calendar text omits account details. Browser code cannot control later sharing, cloud download-folder sync, password-manager behavior, OS screenshots, extensions, or copies in another open tab. Clear affects this tab, plus the optional encrypted envelope in this browser if selected. It does not remotely erase another tab's decrypted memory. No multi-tab deletion guarantee is claimed.

## Credible scale model

The app serves static HTML/modules, one chosen dictionary and optional prerecorded guidance. Account count/record complexity increases work in that person's browser, not a central private-data service. Each tracker is limited to **50 accounts**, **20 events per account**, a **1 MiB plaintext encrypted-save payload** and a **2 MiB import**. The managed public-shell cache has an **8 MiB response-body ceiling**; audio has **12 MiB/256 entries**. Cache metadata/browser memory are outside those response-body ceilings, so these limits do not certify physical 2 GB hardware.

[Reproducible current-source delivery inventory](audits/2026-10-04-privacy-recovery/delivery-scale.json) records every public file and the eager module graph, each language's app body/gzip sizes and explicit arithmetic scenarios. It counts HTML, CSS, favicon, eagerly imported modules, one selected dictionary and the relevant small script font. It excludes worker installation, HTTP headers, TLS, retries and compression negotiation. It is a file inventory, not measured navigation transfer or a load test. Historical navigation timings keep their original manifests.

At **one million independent cold Hindi sessions**, the inventoried gzip app bodies imply **59.110 decimal GB**. If each session additionally plays **1 MiB** of recordings, that adds **1,048.576 GB**; **10 MiB** adds **10,485.760 GB**. These are transparent scenarios, not observed usage. Returning browser caches can reduce downloads; CDN hits reduce origin work but do not mean delivery is free. The full sixteen-language audio library is deployed once, not downloaded by everyone at startup. There is no runtime model-hosting bill: speech generation is build-time work, and the site hosts prerecorded files.

A budget must apply the selected host's current delivered-byte/request rates, included quotas, cache behavior and deployment limits to these scenarios. No rupee price, unlimited capacity, national-population readiness or throughput claim is made. A defined concurrent-traffic exercise and hosting spend/usage observations would be needed before making such claims. The near-term cost risk is repeated optional audio delivery, not account-database storage.
