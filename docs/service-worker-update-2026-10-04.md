# Returning-client update correction — 4 October 2026

An actual returning desktop browser on the production origin retained the six-language gate and dialog after a deliberate reload. A fresh deployment origin displayed all 21 languages and search. This exposed an upgrade gap that public HTTP source-hash checks did not detect. The original worker installed a new cache but did not skip its waiting phase; an open old controlled page could repeatedly receive its cache-first shell.

The corrected worker activates only after every public shell file finishes installation. It never navigates a client and never clears a workspace or user storage. Existing pages retain their loaded modules and in-memory entries. Previous public shell caches are retained while any open page has not attested the exact current release ID. The worker asks each page once for this public-only version; the new page reports its eagerly loaded build ID, while legacy pages do not falsely claim the new version. Once every open page uses current modules, old shells are retired. The handshake works again after a worker restart and persists no client identifiers. An independent **8 MiB response-body ceiling** covers all managed public shells, dictionaries and selected fonts: an install exceeding it discards only the new candidate and defers activation; a new optional locale/font exceeding it is served but not retained. This preserves live predecessor assets rather than evicting a draft's dependencies. The separate 12 MiB/256-clip audio budget is unchanged. Browser cache overhead, HTTP caching and storage eviction remain outside these response-body budgets. Private inputs, files and passwords are never placed in these caches.

An older page's exact already-cached immutable locale hash remains available from its old shell, for supported languages only and without query strings. Current app requests use the current catalogue and current shell; old copy is never substituted for a new locale revision. Static imports are loaded eagerly by the existing public runtime. Existing unchanged script fonts and exact current dictionaries are migrated for offline use.

The new page code checks worker updates without HTTP cache reuse. A controller change may refresh only an already-controlled, untouched language gate. First installation, any language selection, any input/search, any workspace/account/editor/draft, and save/resume views prevent this automatic reload. Older six-language page code predates this guard; its first reload may initiate the worker update, and a subsequent deliberate reload is required to display the new shell. There is no forced old-client reload because the worker cannot inspect whether private form data has been entered.

The rebuilt final release gate passes **100 tests**, including complete-install-before-activation, failure without activation, old-client asset retention, exact locale compatibility, all-current-release cleanup after a restart and upgrade deferral at the shell byte ceiling. Two cases execute the actual runtime controller-change binding and check untouched-gate versus chosen, pending language choice, search/input and private workspace states. These deterministic checks do not replace the actual returning-browser verification, which is recorded separately after publication. Audio recordings, the startup outage recovery/probe algorithm and locale retry delays are unchanged; earlier performance measurements remain qualified by their original source hashes.
